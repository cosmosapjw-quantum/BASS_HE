# E13C4 독립 수치 대조 보고

## 결과와 역할

새 구간 연산과 2차 도함수에 대한 **386개 독립 대조**, 고정된 여섯 입력의
계수에 대한 **632개 대조**가 모두 통과했다. 이는 이 기여자가 수행한 수치·구현
검사이며, 최종 물리 판정이나 생산 적용 결정은 별도 심사자의 범위다.

처음 실행한 경계 검사에서는 `J(0,h)`가 음수 `h`를 그대로 반환하는 오류를
관측했다. 실패 당시 코드와 실제 종료값을 보존했다. 소유자가 폭 검사를
흡수율이 0인 분기 앞에 배치한 뒤, 같은 실패 사례를 포함하는 전체 primitive 대조가
통과했다. 여섯 실제 물리 구간에는 음수 폭이 없으므로 이 오류가 그 입력의
물리 값을 바꾸지는 않았다.

| 실제 실행 | 목적 | 관측 결과 | 실제 종료값 | 경과 시간 |
|---|---|---:|---:|---:|
| `domain_01` | `J(0,-1)` 입력 거부 확인 | 최초 실패 보존 | 1 | 0.078893 s |
| `primitives_01` | 유리수 포함구간·연산·도함수 대조 | 386/386 통과 | 0 | 3.722053 s |
| `coefficients_01` | 원본 CSV 선택·계수·에너지/소스 도함수 대조 | 632/632 통과 | 0 | 0.935748 s |
| `coefficients_portable_01` | 이전 대형 패키지 없이 fixture로 실행되는지 확인 | 같은 632/632 통과 | 0 | 0.843481 s |

마지막 행은 전달 패키지의 이식성 확인이다. 이를 추가적인 독립 물리 증거
632개로 중복 계산하지 않는다. 시간은 이 실행의 관측값이며 성능 비교나
다른 실행환경에 대한 보장은 아니다. 실제 런타임은 Python 3.12.14,
libmpdec 4.0.0이었다.

## 독립 기준의 구성

`rational_reference.py`는 Decimal의 지수·로그·제곱근·거듭제곱을 호출하지
않는다. 정확한 정수와 `Fraction`으로 다음 포함구간을 계산한다.

- 지수함수: 양의 Taylor 합과 명시적인 기하급수 꼬리 상계, 이진 범위 축소,
  양의 구간 제곱. 정수 크기를 제한하기 위한 중간 반올림도 정확한 유리수를
  바깥 방향의 유리수 격자로 옮긴다.
- 로그: `[1,2)`로 범위를 축소한 뒤 양의 atanh 급수와 명시적인 꼬리 상계.
  `ln(2)`도 같은 방식으로 포함한다.
- 제곱근: `k² d ≤ n S² < (k+1)² d`를 정수 산술로 확인하는 제곱근 브래킷.
- 양의 밑의 거듭제곱과 `J`: 위 포함구간의 합성 및 흡수율이 0인 정확한 극한.

주 구현의 출력이 독립 유리수 구간의 양 끝을 모두 포함하는지 검사했다.
따라서 중간의 근삿값 하나를 비교하는 검사보다 강하다. 유리수 기준 자체의
포함 성질과 그 기준으로 검사한 유한 개 구현 사례는 구분한다. 전자가
수학적 포함구간이라고 해서 후자가 모든 가능한 입력에 대한 소프트웨어
정확성 증명으로 바뀌지는 않는다. 유도는 `RATIONAL_REFERENCE.md`에 있다.

실제 검사에는 부호를 가로지르는 구간, 상쇄, 영을 포함하지 않는 작은 분모,
원시 binary64 값의 정확한 변환, 초월함수의 물리적 인수 범위, 잘못된 정의역,
음수 폭, 흡수율이 0인 극한이 포함된다. ambient Decimal 정밀도를 3자리,
반올림을 `ROUND_UP`으로 바꾸어도 주 구현의 직렬화된 결과는 동일했다.
의도적으로 안쪽으로 줄인 지수함수 구간을 검출하는 음성 대조도 포함했다.

`Jet2`는 Taylor 계수가 아니라 실제 1·2차 도함수를 저장한다. 3차 다항식,
양의 2차식의 역수·로그·제곱근·비정수 거듭제곱, 2차식의 지수함수를
각각 독립적인 닫힌 도함수 식과 비교했다. `J`의 도함수도 지수함수 정의에서
따로 계산했다. 같은 식을 다시 자동미분하여 기준으로 삼지 않았다.

원본 OFF/GM `SEGMENTS.csv`와 `STAGES.csv`에서 위 키를 독립적으로 선택했고,
주 구현의 `SIX_CONTROLS.json`에 담긴 행·stage와 정확히 같은지 확인했다.
각 구간의 정규화 시간 `0, 1/4, 1/2, 3/4, 1`에서 저장된 E13C2 계수 정의만
110자리로 평가했다. 총 30개 지점에서 에너지, 외부 소스, 세 종의 흡수율을
주 구현의 점 구간, 해당 지점을 포함하는 1/32 폭의 구간, `Jet2`의 값 구간과
대조했다. 모든 값이 포함되었다. 비활성 종의 값과 두 도함수는 정확히 0이었다.

계수 점 구간의 최대 상대 폭은 약 `1.31046e-57`이다. 이 수치는 주 구현이
반환한 구간의 폭이며, 연속 해의 오차나 새로운 물리 정확도 수치가 아니다.
110자리 값 역시 엄밀한 포함구간으로 취급하지 않았다.

에너지와 소스의 1·2차 도함수는 별도의 닫힌 식과도 대조했다. 예를 들어
`u=h t`, `X=Ωr exp(-4s)+Ωm exp(-3s)+ΩΛ`라 두고,

`b=4Ωr exp(-4s)+3Ωm exp(-3s)`,

`c=16Ωr exp(-4s)+9Ωm exp(-3s)`이면,

`(ln H)'_u=-b/(2X)`, `(ln H)''_u=(cX-b²)/(2X²)`이다.

이를 이용해 `E'_t=-hE`, `E''_t=h²E`,
`q'_t=hq[1-(ln H)'_u]`,
`q''_t=h²q{[1-(ln H)'_u]²-(ln H)''_u}`를 계산했다.
종별 흡수율의 도함수에 대해서는 별도의 수치 기준을 만들었다고 주장하지 않는다.

추가적인 합성 입력 검사는 마스크 분기만 확인한다. 캡처 때 비활성이었던
종은 임의의 높은 에너지에서도 해당 분기에서 0을 반환했고, 활성 HI 분기는
컷오프 근처에서 캡처된 한쪽 연속 연장을 유지했다. 이 합성 검사는 새로운
물리 경로나 새 분광 모델을 실행한 것이 아니다.

## 공유 의존성과 주장 한계

계수 대조는 같은 binary64 상수, 같은 Verner 매개변수, 같은 아핀 기체 경로,
같은 FLRW 정의, 같은 캡처 마스크를 공유한다. 계수의 110자리 평가와 주
구현은 Decimal 초월함수 백엔드도 공유한다. 따라서 이 부분은 독립적인
계수식 번역과 고정밀 점 대조이지, 두 번째 원자 자료 집합이나 완전히 독립적인
수치 라이브러리를 이용한 검증이 아니다. 산술 백엔드와 다른 기준을 쓰는 부분은
앞 절의 유리수 primitive 대조다.

원래 collocation, Gauss 규칙, 연속 reference, first-variation solver는
호출하지 않았다. 저장된 helper에서 해당 함수들을 오류를 내는 금지 함수로
교체한 뒤 계수 객체만 평가했으며, 금지 함수 호출 수는 0이었다. 기체/Newton
히스토리, 원자 광자 출력, 생산 모델 변경도 수행하지 않았다.

부호가 바뀔 수 있는 `abs(δλ)`에는 `Jet2` 미분을 적용하지 않았다. 코드
검토에서는 절댓값 상계가 `value(...)`에서 만들어지고, 검증된 midpoint 적분의
2차 도함수는 부드러운 부호 있는 integrand에서만 계산됨을 확인했다. 전체
잔여항 부등식, 분할 적분의 정리 적용, 주 계산의 최종 판정은 소유자와 별도
최종 심사자가 통합해야 한다.

## 관련 소스가 바뀐 경우의 재실행

다음 명령은 E13C4 패키지 루트에서 실행한다. `--attempt`는 이미 존재하는
폴더를 덮어쓰지 않으므로 새 이름이어야 한다. 변경이 없는 기존 대조를 매번
반복해야 한다는 요구는 아니다.

```bash
python3 evidence/control/run_control.py --attempt primitives_local_01 \
  --script evidence/control/primitive_controls.py \
  --interval code/directed_interval.py

python3 evidence/control/run_control.py --attempt coefficients_local_01 \
  --script evidence/control/coefficient_controls.py \
  --interval code/directed_interval.py \
  --coefficient code/local_enclosure.py \
  --controls inputs/SIX_CONTROLS.json \
  --replay-fixture evidence/control/coefficients_01/PINNED_CAPTURE_FIXTURE.json
```

두 번째 명령은 보존된 정확한 행 fixture와 helper 캡처를 사용한다. 이전
대형 패키지나 원본 연속 solver를 필요로 하지 않는다. 이번 이식성 실행은
원본 CSV를 다시 읽은 것으로 기록하지 않았다.

## 확인한 산술 계약

[Python Decimal 공식 문서](https://docs.python.org/3.12/library/decimal.html)는
`exp`, `ln`의 HALF_EVEN 올바른 반올림, 정확한 `from_float`, 문맥에 영향을
받지 않는 `copy_abs`/`copy_negate`, 이웃 표현값을 주는 `next_minus`/`next_plus`를
설명한다. C 구현의 일반 비정수 `power`는 같은 정확한 반올림 보장이 없으므로
주 구간 구현은 로그와 지수의 포함구간을 합성한다.

[General Decimal Arithmetic 명세](https://speleotrove.com/decimal/daops.html)는
기본 연산의 정확한 결과 후 반올림 규칙과 제곱근의 HALF_EVEN 규칙을 설명한다.
일반 명세는 지수·로그에 1 ulp 오차를 허용하므로, 지수·로그에 대한 더 강한
전제는 위 Python 구현 계약에서 가져온다. 주 구현의 제곱근은 반환값의 제곱
부등식도 방향 반올림 곱셈으로 매번 확인한다.
