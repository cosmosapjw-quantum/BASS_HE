# NCP c64-g3 durable runner Implementation Plan

> **For agentic workers:** Use an available `superpowers:executing-plans` skill for inline execution; use fresh subagents only for disjoint work when available. Missing plugin skills do not block this written plan. Steps use checkbox syntax; execution evidence lives outside the repository.

**Goal:** Implement the approved single-VM, case-parallel BASS_HE execution layer without changing mathematical kernels or scientific admission.

**Architecture:** A single controller owns a local SQLite ledger and immutable result publication. Persistent explicitly spawned workers run one endpoint or one geometry case at a time through the pinned scientific API. Stage barriers, per-call deadlines, payload validation and epoch fencing survive restarts; a systemd template is delivered but not installed without host authorization.

**Tech Stack:** Existing Python >=3.11 package, NumPy 2.3.5 and the repository's DR11E SciPy requirement; Python standard library multiprocessing/sqlite3/hashlib/json. Inspect and lock the actual environment before installing. Numba remains optional and unavailable until original source and its tests/lock are recovered. No MPI/Ray/Dask or container orchestration.

**Spec:** `docs/cloud/ncp-c64g3/DESIGN_KO.md`; parameters in `docs/cloud/ncp-c64g3/RUN_PROFILE_DESIGN.json`; source binding in `docs/cloud/ncp-c64g3/PLAN_BINDING.json`.

## Review Focus

- Final file published before ledger commit: recover the ledger without rerunning the case (T2).
- A native call ignores cancellation, or an old worker sends a late reply: reap the exact owned process and reject old epochs (T3).
- Missing nested cgroup limits or data mount: do not assume unlimited CPUs/RAM or fall back to root disk (T5).
- Small stage width or cache-hit-only timing: do not claim 64-way scaling or count PERF repetition as new science (T6).
- Scientific cache carries a different endpoint certificate, backend or environment: reject mismatches instead of silently recomputing (T1/T2/T4).

## Shared interfaces

Define frozen `CaseSpec(kind, science_fields)` and `Attempt(task_id, run_epoch, number)`. Kinds: `wrong_pair_check`, `control`, `endpoint`, `geometry`. `science_fields` is kind-validated: pair labels, seed or endpoint/certificate hash, rho, depth, panels, source/model/path and backend identity; no PID or elapsed time. Complex values use explicit real/imaginary values; canonical keys preserve exact float64 values without rounding. Reject nonfinite values and bool-as-int input.

`ExecutionBinding` separately records plan/runtime commits, all transitive code hashes including adapters/contracts, Python/library/BLAS/LLVM versions, CPU features and thread policy. Same-task reuse also requires the same admitted binding. Worker count affects run metadata, not the mathematics.

`CaseOutcome(status, payload, diagnostics)` keeps scientific rejection separate from runtime failure. `run_case(spec: CaseSpec) -> CaseOutcome` never substitutes missing or failed values with zero. `task_id(spec: CaseSpec) -> str` returns SHA256 of canonical scientific specification. Certificates are data tied to that exact endpoint/pair, not a transferable `passed=True` token.

`ResultStore(root: Path, binding: ExecutionBinding)` exposes `begin_epoch() -> str`, `claim(spec) -> Attempt`, `commit(attempt, prepared_path) -> CommitReceipt`, `reconcile() -> RecoveryReport`, `load(task_id) -> CaseOutcome | None`. Only the controller writes ledger/final paths. Durable artifact COMMITTED is not the same as a passed 32/64 convergence gate.

`Supervisor.run_ready(specs, workers, store) -> StageReport` uses explicit spawned worker processes and dedicated per-worker IPC. `Controller.run(profile, resume=False) -> RunReturn` advances only a validated stage barrier. Unknown/malformed status is failure, not success.

## Completion and continuation

The supplied Codex task is an implementation request, not a request for another proposal. Execute T0 onward until locally implementable work is complete or an actual mandatory blocker arises. Missing optional acceleration, NCP access or provider authorization affects that lane only. Do not turn scientific HOLD into a reason to skip runner development; do not turn runner PASS into scientific promotion.

The existing 120s numerical-call budget is enforced by owned-worker supervision with logged grace, not an absolute billing guarantee. Long-lived tasks must be checkpointed by the program, not kept alive by the agent conversation. On interruption, read EXECUTION_STATE and receipts, reconcile, and continue only the first unresolved task.
