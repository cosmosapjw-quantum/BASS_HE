## Scientific implementation assessment

**Complex amplitude path.** The code computes the real and imaginary components of a±s b separately as signed scaled pairs before forming their squared norm. This implements the direct sum/difference required by the theory, rather than subtracting nearly equal quadratic densities. In the dangerous mixed case, real components +1e308 and −1e308 cancel before combining with the imaginary component 2e−308. Thus the latter is retained as a nonzero scaled pair by the inspected algorithm. Nonnegative quadratics use mantissa/exponent storage. Packing reports OVERFLOW/UNDERFLOW with a null ordinary float; mathematical zero reports ZERO. U, C, D remain independent computed values, and η handles U=0 with null. As usual, tiny contributions below a dominant norm's binary64 precision can be rounded away; no universal all-scale relative accuracy theorem is established by these finite tests.

**Phase and disk paths.** The phase lower endpoint uses |A−B|/(√A+√B) then squares the result using the scaled representation; it avoids near-equal square-root subtraction. For finite nonnegative binary64 intensities, the intermediate square-root sum itself cannot overflow binary64, and A−B is bounded in magnitude by max(A,B). Zero is handled separately. The upper endpoint is squared without first forming an ordinary floating-point square. The disk path adds error radii as scaled pairs, obtains |z_hat| from the stored C, clamps a negative lower radial bound to zero, and squares both radial bounds. These are approximate binary64 evaluations of the R6-proved real-arithmetic formulas. Theory explicitly disclaims a directed-rounding enclosure certificate, and the actual test report preserves that distinction.

**Admission and weighting.** The raw path requires unweighted amplitudes, common source/phase provenance, and an explicit convention. Coherent density is passed through, with existing weight metadata preserved. Incoherent intensity input returns bounds and C=null. Unknown profile/representation, nonboolean weight metadata, invalid spin, unequal energies, and missing unit/measure metadata are rejected. Exact decimal comparison prevents a near-sharing tolerance from admitting unequal points. Spin averaging requires one singlet and one triplet with matching source identity, producer family, kinematics, preparation, density units, measure, and canonical outgoing energy. Applied weights are either 1 for already-weighted data or 1/4 and 3/4 for unweighted channels. No factor two/four or event-normalization operator is inserted. These are metadata-conditional checks; no physical producer is admitted.

Tests use the corrected source-sign example (7,9,5)/(7,5,9), both spins, common-phase and swap invariance, destructive/zero cases, independently scaled extreme U/C/D controls, phase endpoints, disk endpoint witnesses, weights once, provenance/kinematic rejections, and actual printed source values.
