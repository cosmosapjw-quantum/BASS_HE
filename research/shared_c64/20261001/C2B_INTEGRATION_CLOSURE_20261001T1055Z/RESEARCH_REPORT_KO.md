# C2b — 동결 상태의 force·overlap 적분 검증

**판정: SCOPED_FROZEN_STATE_INTEGRATION_CLOSED.** C2a에 남았던 큰 R의 force 적분과 다섯 m=0 상태 연결의 적분 문제를 해결했다. 새 고유값 계산은 0회다. 원래 상태·물리 연산자·binary64 정밀도와 허용오차를 유지했다. 이 판정은 동결된 유한 상태의 적분에 한정되며 full C2 또는 연속체 인증이 아니다.

## 무엇이 바뀌었나

Force의 Coulomb 모서리에서는 기존 Duffy 변환 뒤에도 길쭉한 셀의 분모가 얇은 변화 구간을 남겼다. 원래 spline knot를 보존하면서 Coulomb 거리 규모에 맞춰 긴 방향을 이등분했다. 핵 모서리에는 두 삼각형 Duffy 적분을 유지했다. 영역이나 피적분함수의 근사는 추가하지 않았다.

서로 다른 R의 상태 겹침에서는 상대 상태의 핵 위치가 원래 적분 셀 내부로 이동한다. 새 좌표 s=√(ξ²−1), θ=acos(η)에 원래 knot와 상대 핵의 위치를 경계로 넣고, 해당 모서리를 물리적 길이 비율에 맞춰 나눴다. 두 상태를 공통 전하 중심 O에 표현하고 각 유한 영역 밖은 0으로 연장했다. 양방향 겹침과 두 자기 노름을 모두 계산했다. 유도는 math/FORCE_DERIVATION_KO.md와 math/OVERLAP_DERIVATION_KO.md에 있다.

두 변경 모두 상태 값이나 목표 결과에 맞춘 분할이 아니라 좌표만으로 정한 분할이다. 차수 수열과 통과 기준은 물리 적분 전에 CONTRACT.json에 고정했다. 유한 차수의 증가량은 경험적 수렴 지표이며 엄밀한 오차 상한으로 해석하지 않는다.

Force 대상은 R=8,16 각각 base/h/p/tail의 8개 쌍과 R2_base 대조군이다. Overlap 대상은 m=0의 11→12→13→14→15→16 다섯 연결, 10→11 m=0 및 15→16 m=1 대조군이다. Overlap의 마지막 세 차수는 자기 노름·양방향 일치·|S|≥0.5 조건도 모두 만족했다. 추가 fallback 차수는 필요하지 않았다.

가장 문제가 컸던 R16_h에서 직접 연산자와 force의 차이는 부모의 약 1.366×10⁻⁷에서 새 q28의 2.483×10⁻¹¹로 줄었다. 같은 파동함수에서 독립 적분 경로가 일치하므로, C2a의 해당 실패는 이 범위에서 적분 해상도 문제로 설명된다. Native 구현만의 오류나 상태 가지 전환의 증거로 해석하지 않는다.

이 결과를 기존 성공 증거에 합치면 R={0.25,0.5,1,2,4,8,16}의 7개 점별 기준이 모두 통과한다. 에너지·h/p/tail·직접 연산자와 독립 구면 앵커 R={0.5,2,8}의 성공 증거는 재계산하지 않고 재사용했다. 18개 R 지점의 두 fixed-m 가지에 대한 34개 인접 연결도 통과했다. 27개 기존 성공 연결은 재사용하고 이번 7개 연결을 반영했다. 위상은 MPI 완료 순서와 무관하게 R 순서로 누적했으며 보존된 계수를 수정하지 않았다. 모든 국소 위상 인자는 +1이다.

## 속도·메모리 개선의 확인 범위

Fortran real64의 독립 곱 SIMD와 patch별 OpenMP, 독립 적분 작업의 OpenMPI 분배를 사용했다. Scalar B-spline 평가를 배열로 묶고 32 patch씩 처리해 전체 고차 점 배열의 동시 할당을 피했다. 합산 순서는 각 patch에서 고정하며 batch 합은 math.fsum으로 결합한다. fast-math, 숨은 저정밀도 및 자동 backend 대체는 사용하지 않는다. 컴파일러·소스·ABI·실행 바이너리의 SHA를 결과에 보존했다.

| 대표 적분의 선택 차수 | 기존 방식의 점 수 | 새 방식의 점 수 | 감소 |
|---|---:|---:|---:|
| R16_h force: 기존 q56 / 새 q28 | 18,069,632 | 4,544,064 | 약 74.9% |
| R15→16 m0 overlap 양방향: 기존 q64 / 새 q32 | 20,971,520 | 5,480,448 | 약 73.9% |

이는 각 적분 검증을 통과한 대표 차수의 점 수 비교다. 차수가 서로 다르므로 같은 workload의 Fortran 또는 MPI 속도 배율이 아니다. 정상 사전검사를 통과한 1-worker 배치에서 overlap 새 q32는 5.279초, 기존 q64는 26.546초였다. 각각 한 번의 작업 경과시간이며 반복 benchmark나 64코어 scaling 결과로 승격하지 않는다.

55개 완료 작업의 최대 RSS는 79,876 KiB(약 78.0 MiB), 최대 작업 시간은 26.546초였다. 이는 측정 RSS이며 사전 설정 주소공간 한도 1.5 GiB와 다르다. 최악의 고차 기준 적분도 streaming 경로 안에서 완료됐다. NCP 64코어·128GB의 실제 scaling은 NOT_RUN이다. 다음 실행은 실제 topology·CPU quota·가용 메모리 검사에 따라 rank/thread를 정해야 한다. 모든 플랫폼에 64 MPI rank를 고정하는 최적화는 하지 않는다.

## 실행 제어 오류와 복구

초기 3-worker 사전검사가 메모리 기준에서 실패했는데도, root의 도구 실행 순서 오류로 4-rank 배치가 시작됐다. 발견 후 해당 실행을 중단했다. 이 최초 실행을 자원 정책 준수 또는 유효한 scaling benchmark로 주장하지 않는다.

완료된 35개 작업은 RESULT·DATA·입력·소스·바이너리 identity를 각각 확인해 부분 증거로 보존했다. 시작됐지만 끝나지 않은 overlap 3건도 그대로 남겼다. 새 1-worker 사전검사를 통과한 뒤 나머지 20개 작업을 새 출력 폴더에서 완료했다. 두 실행 당시 소스 snapshot과 복구 기록을 보존했으며 기존 실패 파일을 덮어쓰지 않았다. 독립 검토가 이 복구와 모든 55개 결과를 별도로 확인했다.

새 overlap 완료 21건과 중단 시도 3건을 합친 24건은 계약 상한 35건 이내다. 물리 계산 배치 시간의 보수적 상한은 약 268.6초로 총 1,800초 예산 안이다. 선택적 2-task MPI/serial 재검사는 이후 가용 메모리 사전검사에서 거부되어 실행하지 않았다. 이때는 사전검사 실패가 launch를 실제로 막았다. 따라서 새 MPI/serial 동등성이나 scaling 증거를 추가했다고 주장하지 않는다. provenance/run_validated_local.py는 실패 시 실행 금지와 timeout 시 실행 process group 종료를 준비한 보조 도구다.

초기 unittest 경로 설정 오류와 수정 후 20개 통과 로그를 함께 보존했다. 제조 적분의 정확한 값·영역 분할·양의 측도·native/Python 일치·잘못된 입력 거부를 확인했다. 제조 파동함수는 물리 고유상태의 정확성 증거로 사용하지 않았다.
